Protocols in Nebula VPN

Filtered networks block different things on different days. Nebula VPN offers several protocols on one server, tests them on the network you are on, and shows which ones carry real data.

VLESS with REALITY

Looks like a visit to a well-known website: the TLS handshake borrows another site's certificate, so there is no domain of yours to block. Often the first to work when everything else is filtered.

VLESS over XHTTP, gRPC and WebSocket

Ordinary HTTPS traffic to your own domain. Because it is plain HTTP, it can travel through Cloudflare or a web host, so it keeps working when your server's address is blocked.

Hysteria2

QUIC over UDP, built for lossy and throttled lines: fast where TCP crawls. With port hopping it moves between ports so a single blocked port does not stop it. Some networks drop UDP; then use one of the TCP protocols.

Shadowsocks-2022 and VLESS Encryption

Encrypted streams with no TLS at all: nothing for a filter to read in the handshake. Fast on lines that leave them alone.

WireGuard

The simplest and fastest where it is allowed. Easy for filters to recognise, so in Iran it often is not.

DNS tunnel

The last resort, for shutdowns when only DNS gets through. It carries traffic inside DNS queries to public resolvers: slow (tens of KB/s), but enough for messages and plain pages. The app tests resolvers on your network and keeps the ones that work.

Automatic

Automatic tries the protocols on your network and keeps a score per protocol and server. A connection is called Protected only after real data has moved through it, and a protocol that stops working is turned off with the reason shown, never swapped behind your back.
